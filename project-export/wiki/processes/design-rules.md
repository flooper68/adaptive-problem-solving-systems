# Process design rules

Rules about how to write any process in this system, learned from retrospectives. Each rule points to the log entry that earned it. New and edited process pages are checked against this list. The retrospective adds, changes, or removes rules with the same approval as a page edit.

A rule enters the list only when it has held across two processes or two retrospectives.

## Moving a rule into the framework

Undecided. A rule is a candidate for `framework/` when all three hold:

1. It is domain-independent — it would hold for an APS system running a factory or a research group, not only this wiki-and-agent setup.
2. It has held across at least two processes or two retrospectives, with log entries to show it.
3. A new system following the framework today would get it wrong without the sentence.

A candidate goes through `knowledge-compilation.md` and `framework-adaptation.md` and lands as a sentence in an existing section, not a new one. Reconsider this test after the third retrospective, or at the first rule that passes it.
