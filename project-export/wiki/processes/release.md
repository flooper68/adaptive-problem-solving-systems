# Framework release

A release names a coherent accepted state of the normative APS framework. It does not turn operational notes or contextual demonstrations into normative requirements.

Before approval:

1. Confirm selected tasks name the problems they address, or explicitly address none, and that material decisions remain recoverable from tasks, problems, evidence, and working-session records.
2. Complete verification and record delayed problem-improvement evidence honestly.
3. Update `framework/CHANGELOG.md` for normative changes.
4. Update maintained application documentation when the framework change would otherwise make it misleading.
5. Compile stable stewardship learning and record remaining gaps.
6. Obtain explicit APS framework maintainer approval for the release state.

After approval, record the release name, exact canonical framework page SHAs, evidence, and handoff in the affected task and working-session record. Chaos House wiki history preserves the accepted state; the R54 repository projection supplies offsite recovery but its Git commit is not release authority. Whether external consumers also require a separately published citable package remains a strategy choice for the release.
