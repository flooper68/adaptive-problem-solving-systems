# Framework feedback sweep

## Purpose

Gather what other Chaos House projects — each a running APS instantiation —
have learned about using the framework, and capture each finding faithfully
as a record in this project. Ends at capture; grooming decides what each
becomes.

## Source and window

All projects except this one. The window starts at the previous sweep's
recorded boundary (first run: each project's creation).

## Procedure

1. Run as an `aps-intake` session with this page as the source definition;
   announce the window per project.
2. For each project, read since the window start: closed grooming and
   retrospective session records, records carrying retro or process findings,
   and process-page changes.
3. Keep only findings that say something about APS itself — a framework
   concept that helped, chafed, was reinvented, misunderstood, or ignored.
   Project-local operational detail stays in its project.
4. Capture one record per coherent finding, faithful to the source's words,
   with a link to the source. No grooming, no tasks, no framework edits in
   the sweep.
5. Close with a digest naming each project's new window boundary.

## Cadence

Due when a month has passed since the last sweep, or on maintainer request.
Grooming checks whether it is due.

## Signal

Read at grooming: findings captured per sweep, and framework changes whose
evidence traces to a swept record.
