# Brainstorming

## Purpose

Discuss an APS idea, task, or research topic with the maintainer, use relevant evidence, and compile reviewable changes into the framework or this concrete APS instantiation.

## Procedure

1. **Frame.** State the topic, intended result, responsible user, relevant problem and parent, boundary, and useful stopping point.
2. **Orient.** Read canonical `framework/` knowledge, declarations, streams, prior decisions, tasks, problems, and session records. Keep missing context explicit.
3. **Explore.** Elicit observations, interpretations, alternatives, decision boundaries, and trade-offs.
4. **Distinguish.** Keep source evidence, interpretation, unresolved questions, authorized decisions, and possible actions separate.
5. **Challenge.** State the problem and strategy element served, contradictions with compiled knowledge or prior decisions, and the strongest case against each material conclusion.
6. **Draft.** Prepare exact proposed canonical-action inputs and page content outside the authoritative wiki. For framework knowledge follow `../knowledge-compilation.md`. Do not create a durable candidate folder or parallel source of truth.
7. **Review iteratively.** Present the draft, incorporate corrections, and repeat. Silence is not approval.
8. **Resolve the stopping point.** On explicit approval, apply the reviewed scope through session-bound canonical actions. Without approval, record a handoff and leave canonical state unchanged.
9. **Deliver accepted work.** Run `../verification.md`, refresh affected current-state views, record changed entities and wiki paths in the session, and confirm R54 backup eventually converges without treating its Git commit as delivery authority.

## Evidence and retention

Raw evidence remains in its source streams. Chaos House tasks, sessions, wiki events, problem histories, and framework changelog preserve the material record. Retain participants, affected problems/tasks, decisions, changed paths, validation, stopping point, and lessons/friction in the working-session record.

## Signal

Read by the retrospective from session records: sessions ending in approved, applied changes ÷ sessions run; approved changes reverted later; maintainer corrections of procedure per session.
