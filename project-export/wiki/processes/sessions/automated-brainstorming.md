# Automated brainstorming

Run brainstorming autonomously on one maintainer-named task or topic, obtain independent agent review, and present the complete proposal for human approval before canonical state changes.

1. Frame and orient exactly as `brainstorming.md` requires.
2. Explore and decide where an interactive session would ask, recording rationale, evidence, uncertainty, and the strongest case against every material proposal.
3. Produce exact draft page content and canonical-action inputs outside the authoritative wiki.
4. Have an independent reviewer examine the complete draft against the frame, evidence, current canonical state, and declared processes. Resolve or explicitly retain each finding.
5. Present the draft, decisions, cases against, reviewer findings, resolutions, and validation plan to the maintainer. Nothing is approved by silence.
6. After explicit approval, apply only the reviewed scope through session-bound canonical actions, verify exact state, refresh affected views, complete the task, and retain the working-session record.

The configured backup repository is never an execution worktree. Its asynchronous projection commit is durability evidence, not approval or completion.
